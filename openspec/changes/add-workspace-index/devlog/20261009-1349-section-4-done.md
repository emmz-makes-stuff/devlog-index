Emmz's answers (asked before coding):
- Archived change name: the `YYYY-MM-DD-` prefix is **stripped** (`2026-03-10-add-retry` → `add-retry`).
  The folder survives in the source path.
- Text before the first `##` in proposal/design/tasks becomes **its own passage if it has body text**; a
  bare `# Title` yields nothing.
- **Context prefix** on non-note passages: `<capability> spec`, `<capability> spec delta (<change>)`,
  `<change> <artifact>` (e.g. `add-retry design`). Notes keep the title prefix, as specified.

My own calls:
- A blank line inside a code fence doesn't split a paragraph. `#` lines inside a fence aren't headings.
- All HTML comments in notes are dropped, including multi-line ones, not just `<!-- Section … -->`.
- A note with no `# ` title gets no prefix. A filename not shaped `YYYYMMDD-HHMM-slug` gives kind `note`
  and no time. An out-of-range date or time counts as no time.
- In specs, only `## Purpose` and `### Requirement:` blocks are kept (`####` scenarios stay inside
  their requirement). `## ADDED/MODIFIED Requirements` headings are dropped.
- Test fixture paths come from a build option (`@import("test_options").fixture_workspace`, an absolute
  path), not the test's working directory.
