# Section 15 done: review fix for symlink precedence

<!-- Section: 15 · Tasks: 15.1 · Base: 2f367ec -->

This builds the two-pass walk that Emmz agreed in the 1731 decision note. It was built after a
`claude` restart, from that note alone.

- **15.1** `sources.discover` now walks in two passes.
  - In `Walk.dir`, a symlink whose `stat` is `.directory` is appended to `Walk.pending` as a
    `Pending { member, abs, rel }`, instead of being walked at once. Symlinked **files** are still
    handled in place.
  - **Pass 1:** `discover` walks every `ok` member's `openspec/`, so every real folder is marked
    visited before any link is followed.
  - **Pass 2:** `discover` drains `pending`. Each round it sorts the queue descending by `abs` and
    pops the smallest, so links found inside a followed target join the queue and still come out in
    path order. It sets `w.member` from the entry, because the queue spans members.
  - The `Walk.openspec` field is gone. Only `discover` used it, so it is now a local join.
  - The per-directory name sort stays. It now just keeps each pass deterministic: precedence no
    longer depends on it.
  - New test, "discover indexes a folder reachable directly and through a link at its real path":
    - `specs/alias` → `specs/auth` is the sibling link. "alias" sorts before "auth".
    - `changes/add-cache/specs/linked` → `specs/auth` is the link across folders. It would classify as
      a delta, and "changes" sorts before "specs".
    - `beta/openspec/specs/outer` → `elsewhere/outer`, which holds the link `nested` →
      `elsewhere/nested/spec.md`. That checks that a link queued during pass 2 is followed.
    - It expects 20 sources (19 fixture + nested), `specs/auth/spec.md` exactly once under `alpha`,
      no `alias` or `linked` in any `rel`, and capability `outer/nested`.
  - The §14 test is unchanged and still passes (21 found, 1 broken).
- The spec and design don't mention symlinks. The behaviour is defined only by the §14 and §15 review
  tasks, so no spec text drifted.
