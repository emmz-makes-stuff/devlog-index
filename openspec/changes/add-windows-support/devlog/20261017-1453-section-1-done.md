# Section 1 done: Windows build feasibility

<!-- Section: 1 · Tasks: 1.1–1.3 · Base: 915056d -->

`zig build -Doptimize=ReleaseFast -Dtarget=x86_64-windows` (run from the Mac, with `make libc` having written
the SDK 26 libc file; the Windows target ignored it) built the vendored `sqlite3`, `sqlite-vec`, `ggml`,
`ggml_cpu`, `llama_common` and `llama_cpp` libraries: 15 of 18 steps succeeded. Only the exe failed, with two
errors in our own code, both in `Quiet` (src/model.zig):

- `std.c.open("/dev/null", …)`: the variadic `open` is rejected under the `x86_64_win` calling convention
  ("parameter of type 'void' not allowed"). Reached via `embed.zig:122` and `update.zig:616`.
- `std.c.dup2(self.saved, std.posix.STDERR_FILENO)` at model.zig:55: on Windows `fd_t` is `*anyopaque`, and
  `STDERR_FILENO` / `dup` results are `c_int`.

So no change to the llama.cpp.zig fork pin or the vendored C is needed, and the 1.2 stop did not trigger.

Task 1.3 (the test binary compiles for Windows) can't be checked yet: the test module is the same code and
hits the same two errors. I moved that check into 2.2's verification in `tasks.md` and did not tick 1.3 as a
separate pass. That was my call as the implementer, not Emmz's.
