Three of the four targets cross-compile from one ubuntu runner. Windows doesn't, and is dropped from this
change on Emmz's call.

**Spike.** A throwaway GitHub Actions run (id 38913803931, ubuntu-24.04, Zig 0.16.0 from the ziglang.org
tarball, sha256 `70e49664a74374b48b51e6f3fdfbf437f6395d42509050588bd49abe52ba3d00`), one job, targets built
sequentially with `-Doptimize=ReleaseFast`, cold cache:

| Target | Result | Time | `file` |
|---|---|---|---|
| x86_64-linux | OK | 381s | `ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, stripped` |
| aarch64-linux | OK | 355s | `ELF 64-bit LSB executable, ARM aarch64, version 1 (SYSV), statically linked, stripped` |
| aarch64-macos | OK | 329s | `Mach-O 64-bit arm64 executable, flags:<NOUNDEFS\|DYLDLINK\|TWOLEVEL\|WEAK_DEFINES\|BINDS_TO_WEAK\|NO_REEXPORTED_DYLIBS\|PIE\|HAS_TLV_DESCRIPTORS>` |
| x86_64-windows | FAILED | 309s | no binary |

macOS needs no SDK when cross-compiling from Linux (the Makefile's SDK 26 libc is only for macOS hosts).

**Windows.** sqlite, sqlite-vec and llama.cpp all compiled (15/18 steps). Two errors, both in our source:
`Quiet` in `src/model.zig:43-57` redirects stderr with `std.c.open` (varargs; `'void' not allowed ... 'x86_64_win'`)
and `std.c.dup2` (takes `*anyopaque` on Windows, got `c_int`). `src/embed.zig:122` and `src/update.zig:616`
fail only by calling `Quiet`. Beyond the compile errors, `src/main.zig` reads `HOME` (lines 71, 99, 134, 151)
for the model cache, and Windows has `USERPROFILE`. A native Windows runner would hit the same errors, so the
design's "native runner" fallback doesn't help here. Decision (Emmz): drop Windows, ship macos-arm64,
linux-x64 and linux-arm64; Windows becomes a future change. proposal, spec, design and tasks were revised
via `/opsx:update` and validate strictly.

**Gotchas.**
- The existing amd64 OrbStack machine `ubuntu` runs under Rosetta on this Apple Silicon Mac, and Zig's
  `translate-c` crashes there (`rosetta error: bss_size overflow`). It can't host the spike. I left Zig 0.16.0
  at `~/zig` and a source copy at `~/spike` on that machine; offer Emmz to delete them.
- That machine's `sh` has no `time`, and OrbStack `run_command` times out near 120s, so long builds need
  detaching.
- Each target took ~5–6 min cold, so the release build will take ~17 min. Consider `actions/cache` for
  `~/.cache/zig` and `.zig-cache` in §4.

**Not proven yet.** The linux-x64 smoke test (`devlog-index --help`) never ran: the Windows failure ended
the job first. Foreign binaries are never executed in CI.
