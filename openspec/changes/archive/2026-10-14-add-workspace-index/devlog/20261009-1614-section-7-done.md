- 7.1 `query.ftsQuery`: terms are runs of ASCII alphanumerics or non-ASCII bytes. Each one is quoted,
  and they're joined with ` OR `, so `"`, `*`, `-`, `:`, `(`, NOT and NEAR can't act as operators. With no
  terms the expression is empty and there are no lexical results. `lexical` runs `ORDER BY
  bm25(passages_fts) LIMIT k`.
- 7.2 `semantic`: vec0 KNN (`embedding MATCH ? AND k = ?`, exhaustive). `merge` (D6) puts passages found
  by both first, ordered by their better rank (lexical breaks ties). The rest **alternate between the
  lexical-only and semantic-only lists**. The first version alternated by raw list position, so it could
  put two semantic hits in a row; the merge unit test caught that. Tests use a hand-built 3-d index
  (`Hand`).
- 7.3 Labels: `member, change|null (main spec), capability, state archived|active, kind, note_time, path
  (absolute), rel, methods, text, thread`. `thread` is always `[]` until §8 fills it; it's in the JSON
  now so the line contract doesn't change. Text output has a header line per result (`N. member ·
  change|main spec (cap) · state · kind · time · lexical + semantic`), the path, then the indented
  text. Notices and errors go to stderr only. With `--json`, stdout carries only result lines, and no
  results means empty stdout (text mode prints "No results.").
- 7.4 Missing index: exit 1 from `index.openRead`, naming `devlog-index update`. Semantic search is
  skipped with a notice (`semantic search skipped: <why>; these results are lexical only`) when: the
  model is not cached, it fails to load, the index was built with another model (the notice names the
  rebuild), the index has no vectors, or the model's dimension differs from the index's. Stale index:
  `freshness.detect` gives "N files changed since the last update are not indexed yet; run:
  devlog-index update". If freshness can't be checked, that becomes a notice and the query still runs.
- **Query never downloads the model** (`ModelProvider.cachedForQuery`: `download_url = null`, task
  `.query` → `ModelNotCached`). A 99 MB download would break the 1 s budget, and `update` fetches the
  model anyway. This is my call. The spec only says "cannot be loaded → lexical + notice", and this
  follows it.
- CLI: `query [--json] [--k N] <text…>`. Several bare words are joined with spaces. `--k` takes 1–100,
  and anything else is exit 2 with the usage line.
- 7.5 Real workspace (ReleaseFast, sandbox off, run from the NOVA-INFRA member, five different queries
  as fresh processes): **0.40 s** for the first run (page cache cold for the model), then **0.04–0.05 s**.
  That's under the 1 s budget. Every run did semantic search (no skip notice), and each printed the
  stale notice, because 5 files had changed since the last update. A query from `identityserver`
  returned NOVA-INFRA passages (cross-repo). I haven't judged whether the results answer the questions:
  that's Emmz's call, and §9's golden set measures it.

Tests: a model-gated test indexes the fixture with the real model and checks that "how long to pause
when the auth server hiccups" finds the retry-policy decision semantically. Hermetic tests cover:
- the archived decision note's labels and that every `--json` line parses;
- at most ten distinct results, with the other member present;
- no index;
- a model failing to load, and another model's index;
- the stale notice with 2 files.

Self-review: Hybrid union retrieval, Result labelling, Output formats (minus threads), Degraded and

have needed but nothing tested; §8 adds the rendering together with its tests. Deferred: there's no
