# Section 11 done: review fixes for correctness

These come from the whole-change review (the 1625 note).

- **11.1 Load the model once.** `ModelProvider.get` (`update.zig`) now returns `mp.embedder` once one is
  loaded. The `Provider` doc comment states the contract: later calls return the loaded embedder.
  The old comment said "called at most once per update", which query and eval broke. The stub can't
  show this bug, because every stub `get` counts as a load, so asserting "loads once" against it would
  only test the stub. Instead, the new model-gated test "ModelProvider loads the model once however often
  it is asked" checks that the `llama_model` handle stays the same across four `get` calls. Task 11.1's
  wording now says this. I also fixed the stale `Embedder.embed` doc comment ("document vector"), which
  is a 12.3 item on the same lines.
- **11.2 No empty error messages.** The `run`/`gather` wrappers in update, status, query and eval now fill
  in their default message whenever the diag is empty, including for errors they recognise. The three
  silent sites now have their own messages:
  - vector length: "the model returned a 7-d vector where 8-d was expected; the index is unchanged"
  - `last_update`: "…is not a timestamp…; rebuild it with: …"
  - `dim`: "…is not a number…; rebuild it with: …"

  `query.rank` now takes a `*query.Diag`, and eval copies its message across. There's one test for each
  site, using `Fixture.exec` (new, read-write SQL) and `Stub.short_vectors` (new).
- **11.3** `workspace.validate` rejects members with the same folder name: "members "a/api" and "b/api"
  have the same folder name, which labels them; rename one". `init` validates too, so it can't write
  such a config. Added a case to "parse rejects bad configs".
- **11.4** The corpus-indexing "Model mismatch" scenario and D3 now say: `update` refuses; `query` returns
  lexical results with a notice naming both models and the rebuild command. The query test now checks
  that the notice names both model URLs, not just the rebuild command.
- **11.5** Reinstalled (ReleaseFast), with the sandbox off, run from NOVA-INFRA. Five fresh queries took
  **0.061–0.113 s** each, including a `jq` pipe, with up to 18 thread entries on a query and no notices.
  `eval` takes 0.18 s for 5 questions. The page cache was warm. Reproducing §7's cold first run
  (0.40 s, model page-in) would need `sudo purge`, which I didn't run. Thread expansion adds only
  SQLite work, not model loading. Within the 1 s budget.

A slip, fixed before the commit: a misfired `perl -0pi` substitution wrote the new `run` wrapper text into
line 1 of `update.zig`. The build caught it, and line 1 is restored. I checked the other files edited with
perl and they're clean. Use Edit for multi-line replacements.
