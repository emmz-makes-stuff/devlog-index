- 6.1 `src/freshness.zig` (D9): `detect(arena, io, ws, db?, diag)` returns `Changes` (added, changed,
  removed). Size and mtime decide first, and a file is hashed only when either differs from `files`. So
  a touched file with identical bytes doesn't count, which matches `update`, where such a file is a
  `touchFile`. A file that vanished after discovery counts as removed. Files under a member that is
  missing right now are not counted (same rule as `update`; `underMissingMember` moved here from
  `update.zig`). With no index, every source counts as added. An unreadable file is `error.ReadFailed`,
  and the message names the path. §7's stale notice reuses `detect`.
- `src/status.zig` and `status [--json]` in `main.zig`: workspace name and root, the index path, each
  member's passage count (`files.member` = basename of the member path) or `missing (<why>); N indexed
  passages kept`, files changed since the last update, last update (UTC, ISO 8601, or "never"), and
  whether the model is cached (with its path). `--json` writes one object on one line
  (`std.json.Stringify`). Fields: `workspace, root, index, indexed, members[{name,path,status,passages}],
  files_changed, last_update|null, model{cached,path}`.
- **No index is not an error for `status`**: it prints "index: not built yet; build it with:
  devlog-index update", and every source counts as changed. Exit 0. Another schema or an unreadable
  index is exit 1, naming `devlog-index update --rebuild`. This is my call; the spec doesn't cover
  `status` without an index. `query` (§7.4) must still exit non-zero.
- `index.openRead` is the shared read-only open (`NoIndex`, `SchemaMismatch`, `IndexBusy`,
  `IndexUnreadable`, each with a message). §7 should use it.

Emmz's answer (asked at the start of the section):
- **Readers during an update: WAL mode.** `Index.open` sets `PRAGMA journal_mode = WAL`, which persists
  in the file. `status`/`query` now read the last committed index while a 12-minute update is writing.
  The real workspace's index was converted by an incremental update this session (`PRAGMA journal_mode`
  → `wal`).
- **`--rebuild` no longer renames over a live index.** In my question I'd offered "remove stale -wal/-shm
  files". That is unsafe if a reader has the old index open, because the new file would be paired with
  the old `-wal`/`-shm`. Instead `swapIn` copies the rebuilt database into the live file through the
  SQLite backup API (`Db.replaceWith`), so readers see either the old index or the new one. It renames
  only when no index exists yet. The rebuild test now holds a reader open across the rebuild and checks
  it sees the new model and every vector afterwards.
