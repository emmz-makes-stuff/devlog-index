Emmz's answers (asked before coding):
- `init` with a missing member or one without `openspec/`: **write it, warn on stderr** per member.
- Parsing is **strict**: unknown fields rejected by name; empty name, empty member list, empty member
  path and duplicate members (compared after resolution, so `api` = `./api/`) rejected. `init` runs the
  same `validate`, so it can't write a config `parse` would reject.
- Member paths: **any path**. Relative resolves against the config's directory (`../x` allowed), absolute
  is used as-is, both normalised.

Parsing goes through `std.json.Value` rather than a typed struct so the unknown field can be named in
the error (`std.json`'s `error.UnknownField` doesn't say which).

Not wired yet: no command calls `resolve` because `update`/`query`/`status`/`eval` don't exist until §5+.
Each must call `workspace.resolve(arena, io, try std.process.currentPathAlloc(io, arena), &diag)` and
print `diag.message` on error. Missing members are surfaced via `Member.status` for §5.2 / §6.1 to report.
